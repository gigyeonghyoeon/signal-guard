## 1. 개요

### 1.1 목적

본 문서는 Signal Guard의 **누가, 어떤 목표를, 어떤 흐름으로 달성하는지**(유스케이스)와 **구현 단위로 쪼갠 사용자 가치**(사용자 스토리)를 한곳에 고정한다. 설계 화면·API·테스트 케이스는 본 문서의 UC·US ID를 헤더에 적는다.

### 1.2 문서 관계

```
제안요청서(RFP)
        │
        ▼
프로젝트정의서 (왜·범위)
        │
        ▼
제안요청서요구사항대응표 (RFP 39건을 어디에)
        │
        ▼
요구사항정의서 (무엇을, 검증 가능하게)     ← FR / NFR ID 정본
        │
        ▼
본 문서 (누가·어떻게 쓰는가)             ← UC / US ID 정본
        │
        ▼
백로그WBS.md (언제·누가·얼마나)          ← 스프린트·WBS 정본
        │
        ▼
설계서 / 테스트 계획 / 주간 보드
```

요구사항정의서 5장은 **목록과 대표 흐름**만 둔다. 본 문서가 유스케이스 상세와 스토리 수용 기준의 정본이다. FR ID는 요구사항정의서를 바꾸지 않고 참조한다.

### 1.3 작성 원칙

| 원칙 | 적용 |
|------|------|
| 액터 중심 | 유스케이스는 액터의 목표 단위다. 화면 한 장이 곧 UC가 아니다 |
| 추적성 | 모든 UC는 FR/NFR과, 모든 US는 UC·FR과 연결한다 |
| 범위 | MVP 제외(현장 신호기 실제어, 전국 전수, ML, 지도 1차)는 스토리로 올리지 않는다. 선택 요구만 선택 스토리로 남긴다 |
| 원본 불변 | 수집·검지·통제 스토리의 수용 기준에 “원본 수신을 덮어쓰지 않는다”를 반복한다 |
| INVEST | 스토리는 독립·협상 가능·가치 있음·추정 가능·작음·테스트 가능하게 쪼갠다 |

### 1.4 우선순위

요구사항정의서와 동일하다. **필수** = 12~13주 테스트 필수 통과, **중요** = 일정 허용 시 1차, **선택** = 2단계 또는 여유 주간.

## 2. 액터

| 액터 | 유형 | 목표 | 권한 요약 |
|------|------|------|-----------|
| 운영자 | 주 액터 | 신호정보 품질을 관제하고 통계로 보고한다 | 대시보드·오류 조회, 이슈 확인·코멘트, 통계·내보내기. **통제 불가** |
| 관리자 | 주 액터 | 오류를 닫고 기준(계획·임계값·계정·수집 대상)을 유지한다 | 운영자 권한 + 정보/계획 통제, 현장 통제 요청, 이슈 종료, 계정·설정 |
| 시스템 | 주 액터 | 수집·검지·자동 정보 통제·이슈 생성·집계를 수행한다 | 스케줄 실행, 규칙 적용, 제공 계층 보정, 로그 |
| 실시간 API | 부 액터(외부) | 교차로 맵·8방향 잔여시간·점등상태를 제공한다 | `IF-EXT-001`, 일 5,000회 |
| UTIC | 부 액터(외부) | TOD·SIGNALMAP·교차로 기반정보를 제공한다 | `IF-EXT-002`, 승인 대기. 미승인 시 대체 경로 |

발주 원형(한국도로교통공단·센터 관제원)의 현장 역할은 수업에서 **운영자/관리자 페르소나**로 대체한다.

**공통 전제:** 사람 액터의 모든 UC는 로그인(US-ADM-01)이 선행한다. 비로그인 접근은 거부한다.

### 3.1 포함·확장 관계

```
UC06 실시간 관제
  ├─ include → (로그인)
  └─ extend  → UC11 원본/제공 대조 (상세 화면에서)

UC07 이슈 확인 및 통제
  ├─ include → UC03 재검증
  ├─ include → UC11 통제 이력 기록
  └─ extend  → UC02 계획 수정 (계획 통제 시)

UC01 수집 완료
  └─ include → UC03 오류 검지
                 ├─ extend → UC04 자동 정보 통제 (해결 가능)
                 └─ extend → UC05 이슈 등록 (해결 불가)
```

현장 신호기 **실제어는 유스케이스가 아니다.** UC07의 현장 통제는 요청 기록만 한다 (CON-003).

### 3.2 유스케이스 다이어그램 (논리)

```
                    ┌─────────────┐
     실시간 API ───►│             │◄─── UTIC (승인 시)
                    │   시스템    │
                    │ UC01~05,11  │
                    └──────┬──────┘
                           │ 검지 결과
              ┌────────────┼────────────┐
              ▼            ▼            ▼
         ┌────────┐   ┌────────┐   ┌────────┐
         │ 운영자  │   │ 관리자  │   │ 관리자  │
         │ UC06    │   │ UC07    │   │ UC09    │
         │ UC08    │   │ UC10    │   │         │
         │ UC11    │   │ UC02,11 │   │         │

```

핵심 가치 사슬: **수집(UC01) → 계획(UC02) → 검지(UC03) → 자동통제(UC04) 또는 이슈(UC05) → 관제(UC06) → 사람 통제(UC07) → 이력(UC11)**. 통계(UC08)·계정(UC09)·설정(UC10)이 이를 지탱한다.

### UC01 실시간 신호 데이터 수집

| 항목 | 내용 |
|------|------|
| 주 액터 | 시스템 |
| 부 액터 | 실시간 API |
| 우선순위 | 필수 |
| 관련 화면 | 설정(쿼터·주기 조회), 대시보드(수신 지연) |
| 관련 요구 | FR-COL-001~005, FR-STO-001, IF-EXT-001, CON-001 |

**개요**  
설정 주기가 되면 인천 표본 교차로의 맵·8방향 상태를 호출하고, 원본과 정규화 계층에 나눠 저장한다. 원본은 이후 어떤 통제도 덮어쓰지 않는다.

**사전조건**

1. 수집 대상 표본과 주기가 설정되어 있다 (UC10).
2. 당일 실시간 API 호출 수가 5,000 미만이다.
3. 인증키가 런타임에 존재한다 (소스 저장소 평문 커밋 금지).

**사후조건**

1. 성공 교차로의 원본 수신과 정규화 상태가 저장된다.
2. 시스템 수신 시각이 기록된다.
3. 당일 호출 수가 증가한다.
4. 수집 직후 UC03이 시작된다.

**기본 흐름**

1. 스케줄러가 수집 주기를 감지한다.
2. 쿼터 잔량을 확인한다. 한도 근접이 아니면 계속한다.
3. 교차로 맵(`/crsrd_map_info`)이 주기상 필요하면 인천 교차로를 수집해 마스터를 갱신한다.
4. 표본 교차로에 대해 `/tl_drct_info`를 호출한다. 직전 주기 실패 교차로를 우선한다.
5. `resultCode = K0`인 응답의 원본을 `signal_status_raw`에 추가(INSERT)한다.
6. `...RmndCs`를 초로 변환하고 점등상태 코드를 표준화해 제공 계층 초기값으로 저장한다.
7. 수신 시각·배치 ID를 남기고 UC03을 호출한다.

**대안**

| ID | 조건 | 동작 |
|----|------|------|
| A1 | 맵 수집 주기가 아님 | 3을 건너뛰고 상태만 수집한다 |
| A2 | 키가 없는 데모 환경 | 시드/픽스처로 동일 저장 경로를 탄다. 시연 환경은 실API 또는 녹화를 명시한다 |

**예외**

| ID | 조건 | 동작 |
|----|------|------|
| E1 | HTTP 504, `SERVICETIMEOUT_ERROR`, 연결 타임아웃 | 해당 주기를 실패로 기록하고 재시도한다. 웹 앱은 기동을 유지한다 |
| E2 | 일부 교차로만 실패 | 실패 ID·시각·코드를 남기고 다음 주기에 우선 수집한다. 연속 실패는 R07로 UC03에 전달한다 |
| E3 | 당일 호출이 한도에 도달·근접 | 신규 호출을 막고 대시보드에 쿼터 경고를 표시한다 |
| E4 | 인증 오류 | 재시도하지 않고 운영 알림(화면 경고)을 남긴다 |

**수용 기준**

- 인천 교차로가 `crsrdId`로 마스터에 있고 상태와 조인된다.
- 지정 주기로 8방향 잔여시간·점등상태가 저장된다.
- 원본 `18000`은 정규화 계층에서 `180`초이다.
- 당일 호출이 5,000을 넘지 않는다.

### UC02 신호 계획 적재·수정

| 항목 | 내용 |
|------|------|
| 주 액터 | 시스템, 관리자 |
| 부 액터 | UTIC |
| 우선순위 | 필수 (UTIC 일 1회 수집은 중요, 승인 의존) |
| 관련 화면 | 신호 계획 |
| 관련 요구 | FR-PLN-001~004, FR-MON-005, FR-CTL-003, IF-EXT-002 |

**개요**  
교차로·방향·현시 단위의 정규화 계획을 저장한다. 출처는 UTIC / 수동등록 / 추정 / 시드 중 하나다. 관리자는 미매핑을 확정하고 계획을 수정할 수 있다.

**사전조건**

1. 교차로 마스터가 있다 (UC01).
2. 계획 수정·매핑 확정은 관리자 세션이다. 운영자는 조회만 가능하다.

**사후조건**

1. 계획이 동일 스키마로 조회된다.
2. 매핑된 교차로만 이후 UC03의 계획 대조 대상이 된다.
3. 관리자 수정은 감사 로그·통제 이력(`PLAN_UPDATE`)에 남는다. 원본 수신은 변하지 않는다.

**기본 흐름 (시스템 적재)**

1. UTIC가 승인되어 있으면 일 1회(또는 변경 시) 기반정보·TOD·현시구성·SIGNALMAP을 수집한다.
2. `INT_NO`↔`crsrdId` 매핑이 확정된 교차로에 정규화 계획을 적재하고 출처를 `UTIC`로 둔다.
3. 매핑 미확정 교차로는 계획 대조를 건너뛴다.

**기본 흐름 (관리자 수정)**

1. 관리자가 신호 계획 화면에서 교차로를 연다.
2. TOD 구간, 현시 순서, 유지시간, 사이클을 수정하고 저장한다.
3. 시스템이 해당 교차로에 UC03 재검증을 실행한다.

**대안**

| ID | 조건 | 동작 |
|----|------|------|
| A1 | UTIC 미승인 | 우선순위 (1) 운영자(관리자) 등록 (2) 최근 정상 주기 추정 (3) 시드. 출처를 화면에 표시한다. 미승인은 결함이 아니다 |
| A2 | 이름·좌표 근접 후보가 있음 | 시스템이 매핑 후보를 제시하고 관리자가 확정한다 |

**예외**

| ID | 조건 | 동작 |
|----|------|------|
| E1 | 운영자가 계획 수정을 시도 | 거부하고 감사 로그를 남긴다 |
| E2 | 매핑 해제 | 해당 교차로는 실시간 모니터링만 하고 계획 대조를 하지 않는다 |

**수용 기준**

- 출처가 `UTIC` / `수동등록` / `추정` / `시드` 중 하나로 저장된다.
- UTIC 없이도 최소 1개 표본 교차로에서 계획 대조가 수행된다.
- 운영자는 조회만 가능하다.

### UC03 오류 검지

| 항목 | 내용 |
|------|------|
| 주 액터 | 시스템 |
| 우선순위 | 필수 |
| 관련 화면 | 대시보드, 교차로 상세, 오류 목록 |
| 관련 요구 | FR-VAL-001~004, R01~R12 |

**개요**  
정규화 직후(또는 재검증 요청 시) 규칙 엔진이 품질·정합성·일관성·수신 품질·계획 대조를 수행하고 등급을 부여한다.

**사전조건**

1. 해당 배치의 정규화 상태가 있다.
2. 규칙 임계값이 설정 테이블에 있다 (코드 하드코딩만으로 동작하지 않음).

**사후조건**

1. 각 판정에 규칙 ID와 등급(INFO/WARN/ERROR/CRITICAL)이 붙는다.
2. 해결 가능이면 UC04, 해결 불가이면 UC05로 분기한다.
3. 미매핑 교차로는 계획 대조(R05, R10 등 계획 의존 규칙)를 건너뛴다.

**기본 흐름**

1. 엔진이 설정 테이블의 임계값을 읽는다.
2. R01~R12를 교차로·방향 단위로 적용한다.
3. 매핑된 교차로는 같은 시각·같은 방향의 유효 계획과 점등·잔여시간을 대조한다.
4. 등급을 부여한다. WARN 반복은 승격할 수 있다.
5. 해결 가능/불가 분류 후 UC04 또는 UC05를 호출한다.

**대안**

| ID | 조건 | 동작 |
|----|------|------|
| A1 | 관리자 재검증 (UC07) | 동일 엔진을 해당 교차로에만 실행한다 |
| A2 | 감시 제외 기간 | 신규 이슈를 만들지 않는다. 검지 로그는 남길 수 있다 |

**예외**

| ID | 조건 | 동작 |
|----|------|------|
| E1 | 페이로드 파싱 실패 | R12로 판정. 자동 매핑 가능하면 UC04, 아니면 UC05 |
| E2 | 계획 없음·미매핑 | 상태 품질 규칙만 적용하고 계획 대조는 생략한다 |

**수용 기준**

- 규칙별 정상/경계/오류 테스트가 기대 판정과 일치한다.
- 충돌 현시 동시 녹색은 CRITICAL이다.
- 계획이 “직진 녹색 유지 30초”인 구간에 해당 방향이 적색이면 불일치가 발생한다.
- 관리자가 임계값을 바꾸면 다음 검증부터 반영된다.

### UC04 자동 정보 통제

| 항목 | 내용 |
|------|------|
| 주 액터 | 시스템 |
| 우선순위 | 필수 |
| 관련 화면 | 대시보드(자동보정 N건), 교차로 상세, 통제 이력 |
| 관련 요구 | FR-VAL-005, FR-CTL-001~002, FR-CTL-005 |

**개요**  
데이터 품질 문제로 참값을 소프트웨어가 복원할 수 있으면 제공 계층만 보정한다. 원본 수신은 INSERT 이후 불변이다.

**사전조건**

1. UC03이 해당 판정을 “해결 가능”으로 분류했다.
2. 동일 규칙이 짧은 시간에 반복 승격 조건에 아직 도달하지 않았다.

**사후조건**

1. 제공 계층 값이 변경된다. 원본 행은 동일하다.
2. 보정 로그에 규칙 ID, 전/후, 시각, 신뢰도, 액터=`시스템`, 유형=`AUTO_INFO`가 남는다.
3. 대시보드 자동보정 건수가 증가한다.

**기본 흐름**

1. 규칙 유형에 따라 제공 계층을 보정한다. 예: R08 중복 제거, R12 코드 매핑, 수집 공백 시 잔여시간 1초 감소(계획·직전 정상과 모순 없을 때), 단일 필드 결측을 직전 정상 프레임으로 채움.
2. 원본 테이블에 UPDATE/DELETE를 하지 않는다.
3. 로그를 남기고 제공 계층을 대시보드 기본 표시로 쓴다.

**예외**

| ID | 조건 | 동작 |
|----|------|------|
| E1 | 연속 결측, 보정 실패 | 자동 통제를 하지 않고 UC05로 넘긴다 |
| E2 | 동일 규칙 단기 반복 | 자동 통제를 멈추고 UC05로 승격한다 |
| E3 | 보정 값이 계획과 모순 | 타이머 보간을 적용하지 않고 이슈로 올린다 |

**수용 기준**

- 중복 수신은 제공 계층에서 제거되고 원본은 남는다.
- 교차로 상세에서 원본과 제공 값을 나란히 볼 수 있다.
- 자동보정 테스트 전후 원본 스냅샷(또는 해시)이 동일하다.

### UC05 이슈 등록

| 항목 | 내용 |
|------|------|
| 주 액터 | 시스템 |
| 우선순위 | 필수 |
| 관련 화면 | 오류·이슈 목록, 대시보드 미처리 건수 |
| 관련 요구 | FR-ISS-001, FR-VAL-006 |

**개요**  
시스템이 참값을 알 수 없는 오류를 OPEN 이슈로 올려 관제 대상으로 만든다.

**사전조건**

1. UC03이 “해결 불가”로 분류했거나 UC04가 실패·승격했다.

**사후조건**

1. OPEN 이슈가 1건 존재한다 (교차로·규칙·미종료가 같으면 신규가 아니라 갱신).
2. 대시보드 미처리 건수와 오류 목록에 즉시 반영된다.
3. CRITICAL(특히 R06)은 제공 차단을 기본으로 검토한다 (UC07·FR-CTL-002).

**기본 흐름**

1. 동일 교차로·규칙·미종료 이슈를 조회한다.
2. 없으면 OPEN 이슈를 생성한다. 필드: 교차로, 방향, 규칙 ID, 등급, 발생시각, 원본/보정값, 추정 원인, 상태.
3. 있으면 발생 시각·원본/보정값·등급을 갱신하고 중복 OPEN을 만들지 않는다.
4. ERROR/CRITICAL은 목록 상단 또는 배지를 갱신한다.

**대안**

| ID | 조건 | 동작 |
|----|------|------|
| A1 | 감시 제외 교차로 | 이슈를 생성하지 않는다 |
| A2 | R06 CRITICAL | 이슈 생성과 함께 해당 교차로 정보 제공을 기본 차단한다. 신호기 명령은 보내지 않는다 |

**수용 기준**

- 해당 조건 발생 시 OPEN 이슈가 목록과 미처리 건수에 나타난다.
- 동일 미종료 이슈가 있으면 건수가 늘어나지 않고 기존 이슈가 갱신된다.

### UC06 실시간 관제

| 항목 | 내용 |
|------|------|
| 주 액터 | 운영자, 관리자 |
| 우선순위 | 필수 |
| 관련 화면 | 종합 대시보드, 교차로 상세, 오류·이슈 목록 |
| 관련 요구 | FR-MON-001~003, FR-MON-003-1(선택), FR-MON-006(선택), NFR-PER-001, NFR-USA-002 |

**개요**  
로그인 직후 한 화면에서 운영 상태·등급·지연·자동보정·미처리 이슈를 보고, 교차로·이슈로 들어간다. 값을 바꾸지 않는다.

**사전조건**

1. 운영자 또는 관리자로 로그인되어 있다.
2. 최소 한 번의 수집·검지가 수행되었거나 시드가 있다.

**사후조건**

1. 사용자는 현재 이상 교차로와 미처리 이슈를 식별한다.
2. 데이터는 변경되지 않는다 (조회 전용).

**기본 흐름**

1. 로그인 후 종합 대시보드가 열린다. 전체/정상/경고/오류 교차로 수, 수신 지연, 자동보정 건수, 미처리 이슈, 시간대 오류 추이가 보인다.
2. 오류 교차로 또는 이슈 배지를 선택한다.
3. 필터(유형·등급·기간·교차로·상태)로 목록을 좁힌다.
4. 교차로 상세에서 8방향 점등·잔여시간, 계획 대비, 최근 검증 타임라인, 원본 vs 제공 값을 본다.
5. 수집 공백이면 UI 타이머가 잔여시간을 1초씩 감소 표시하되, 추정임을 구분하고 원본은 바꾸지 않는다.

**대안**

| ID | 조건 | 동작 |
|----|------|------|
| A1 | 웹소켓 미구현 | 설정 주기 폴링으로 목록·배지를 갱신한다. 미구현은 결함이 아니다 |
| A2 | 지도 시각화 미포함 | 테이블·카드 관제로 충분하다. FR-MON-006 미포함은 결함이 아니다 |

**예외**

| ID | 조건 | 동작 |
|----|------|------|
| E1 | 통계·대시보드 로딩 지연 | 3초를 넘기면 진행 표시. 표본 규모에서 5회 중 4회 이상 3초 이내 |
| E2 | 수집 장애 중 | 마지막 수신 시각과 실패 이유를 보여 주고 화면은 유지한다 |

**수용 기준**

- 로그인 후 추가 이동 없이 핵심 지표가 보인다.
- 필터 결과가 조건과 일치한다.
- 원본과 제공 값이 다르면 둘 다 보인다.
- 운영자는 이 화면에서 제공 값·계획을 수정할 수 없다.

### UC07 이슈 확인 및 통제

| 항목 | 내용 |
|------|------|
| 주 액터 | 관리자 |
| 부 액터 | 운영자(확인·코멘트만) |
| 우선순위 | 필수 |
| 관련 화면 | 오류·이슈 상세, 신호 계획, 통제 이력 |
| 관련 요구 | FR-ISS-002~004, FR-CTL-002~004, NFR-SEC-003 |

**개요**  
관리자가 이슈를 생명주기에 따라 처리하고, 오류 위치에 맞는 통제로 닫는다. 통제는 정보 / 계획 / 현장 요청 세 갈래이며 원본 수신은 불변이다.

**사전조건**

1. OPEN(또는 ACK/IN_PROGRESS) 이슈가 있다.
2. 통제·종료는 관리자 권한이다.

**사후조건**

1. 이슈 상태가 허용된 전이만 반영된다.
2. 통제 이력이 남고 재검증(UC03)이 해당 교차로에 실행된다.
3. 원본 수신 레코드는 변경되지 않는다.

**기본 흐름 (정보 통제)**

1. 관리자가 이슈를 열어 ACK한다.
2. 제공 값을 대체하거나, 교차로·방향 제공을 일시 차단하거나, 추정 타이머 표시를 선택한다.
3. 시스템이 제공 계층만 변경하고 `MANUAL_INFO` 또는 `PUBLISH_BLOCK` 이력을 남긴다.
4. 재검증 후 상태가 정합하면 RESOLVED → CLOSED로 진행한다.

**기본 흐름 (계획 통제)**

1. 관리자가 원인을 계획 오류로 판단한다.
2. UC02로 계획을 수정한다 (`PLAN_UPDATE`).
3. 재검증에서 상태와 계획이 맞으면 이슈를 해결 처리한다.

**기본 흐름 (현장 통제 요청)**

1. 관리자가 R06 등 현장 등화기 문제로 판단한다.
2. 현장 통제 요청을 등록한다 (교차로, 방향, 규칙 ID, 요청 내용, 상태 OPEN/ACK/DONE).
3. 해당 교차로 정보는 기본 제공 차단한다.
4. **신호제어기에 점등·주기 명령을 전송하지 않는다.**
5. 요청이 이슈와 연결되고, 현장 확인 후 이슈를 닫을 수 있다.

**대안**

| ID | 조건 | 동작 |
|----|------|------|
| A1 | 오탐 | `FALSE_POSITIVE` 후 종료. 규칙 완화는 UC10 설정 변경으로만 한다 |
| A2 | 유지보수 | 교차로를 기간 지정 감시 제외한다. 기간 종료 후 자동 재개 |
| A3 | 운영자 | 코멘트·ACK 수준의 확인만 가능. 값/계획/현장 요청/종료는 불가 |

**예외**

| ID | 조건 | 동작 |
|----|------|------|
| E1 | 허용되지 않는 상태 전이 | 거부하고 이력을 남긴다 |
| E2 | 운영자의 통제 시도 | 거부(403 동등)와 감사 로그 |
| E3 | 정보 통제만으로 CRITICAL 충돌 녹색을 정상 처리 | 허용하지 않는다. 현장 통제 요청이 필요하다 |

**이슈 상태**

```
OPEN → ACK → IN_PROGRESS → RESOLVED → CLOSED
         ↘ FALSE_POSITIVE ↗
```

**수용 기준**

- 운영자는 값/계획/현장 요청을 할 수 없다.
- 관리자 수정 후 재검증이 실행되고 원본은 그대로다.
- R06에서 현장 통제 요청을 남기면 이력이 조회되고 외부 신호기 API 호출은 0건이다.
- 모든 상태 변경에 사용자·시각·코멘트가 남는다.

### UC08 통계 조회·내보내기

| 항목 | 내용 |
|------|------|
| 주 액터 | 운영자, 관리자 |
| 우선순위 | 필수 |
| 관련 화면 | 통계·리포트 |
| 관련 요구 | FR-MON-004, FR-STO-003, NFR-PER-001 |

**개요**  
사전 집계 테이블로 유형·기간·교차로 통계를 조회하고 CSV(또는 인쇄)로 내보낸다.

**사전조건**

1. 로그인되어 있다.
2. 시간/일/주/월 집계 배치가 최소 한 번 돌았거나 조회 시점에 집계가 있다.

**사후조건**

1. 화면 필터와 동일한 조건의 파일이 내려간다.
2. 원본 풀스캔으로 통계를 만들지 않는다.

**기본 흐름**

1. 사용자가 기간·교차로·규칙 필터를 지정한다.
2. 시스템이 집계 테이블에서 오류율, 다발 교차로, 규칙별 발생, 자동보정 vs 수동조치 비율을 표시한다.
3. CSV 또는 인쇄를 요청하면 현재 필터를 반영해 내보낸다.

**예외**

| ID | 조건 | 동작 |
|----|------|------|
| E1 | 집계 미생성 | 빈 결과가 아니라 “집계 없음/배치 대기”를 안내한다 |
| E2 | 조회 3초 초과 | 진행 표시. 표본 규모 목표 3초 이내 |

**수용 기준**

- 기간을 바꾸면 집계가 다시 표시된다.
- CSV 컬럼·행이 화면 필터와 일치한다.
- 표본 규모에서 통계 화면이 3초 이내이다.

### UC09 계정·권한 관리

| 항목 | 내용 |
|------|------|
| 주 액터 | 관리자 |
| 우선순위 | 필수 |
| 관련 화면 | 로그인, 계정 |
| 관련 요구 | FR-ADM-001, NFR-SEC-001~002 |

**개요**  
역할을 운영자·관리자로 두고 계정을 등록·수정·삭제한다. 비밀번호는 해시 저장한다.

**사전조건**

1. 최초 관리자 시드가 있다.
2. 이후 계정 CRUD는 관리자만 수행한다.

**사후조건**

1. 변경된 역할이 다음 요청부터 API·메뉴에 적용된다.
2. 비밀번호 평문이 저장·로그되지 않는다.

**기본 흐름**

1. 관리자가 계정 화면에서 사용자를 등록하고 역할을 부여한다.
2. 해당 사용자는 로그인 후 역할 메뉴만 본다.
3. 수정·삭제도 관리자만 한다.

**예외**

| ID | 조건 | 동작 |
|----|------|------|
| E1 | 비로그인 보호 자원 접근 | 로그인으로 보내거나 401 |
| E2 | 운영자가 관리자 API 호출 | 403 동등, 감사 로그 |
| E3 | 잘못된 자격 증명 | 실패 로그. 계정 열거를 과도하게 드러내지 않는다 |

**수용 기준**

- 비로그인 사용자는 보호된 페이지/API에 접근할 수 없다.
- 운영자 계정으로 제공 값 수정·계획 수정·계정 삭제·현장 통제 요청이 거부된다.
- 비밀번호가 평문으로 저장되지 않는다.

### UC10 운영 설정

| 항목 | 내용 |
|------|------|
| 주 액터 | 관리자 |
| 우선순위 | 필수 |
| 관련 화면 | 설정 |

**사전조건**

**사후조건**

1. 다음 수집 주기·다음 검증부터 새 설정이 적용된다.
2. 설정 변경 이력이 남는다.

**기본 흐름**

2. 수집 주기와 R02/R03/R04/R07 등 임계값(초, 횟수, 등급)을 수정한다.
3. 쿼터 사용량(사용/한도)을 확인한다.
4. 저장 후 시스템이 다음 배치부터 반영한다.

**예외**

| ID | 조건 | 동작 |
|----|------|------|
| E1 | 주기를 줄여 일 5,000을 초과할 전망 | 저장 시 경고하거나 호출을 한도에서 절단한다. 한도 초과 호출은 하지 않는다 |
| E2 | 운영자가 설정 변경 | 거부 |

**수용 기준**

- 교차로 추가·제외가 다음 주기부터 반영된다.
- 임계값 변경 후 재검증이 새 값을 따른다.
- 대시보드 또는 설정에 쿼터 사용량이 보인다.

### UC11 통제 이력·원본 대조 조회

| 항목 | 내용 |
|------|------|
| 주 액터 | 시스템(기록), 관리자·운영자(조회) |
| 우선순위 | 필수 |
| 관련 화면 | 교차로 상세, 통제 이력 |
| 관련 요구 | FR-CTL-001, FR-CTL-005, FR-STO-001, DAR-N-004 |

**개요**  
모든 통제를 이력으로 남기고, 사용자는 원본과 제공값을 구분해 본다. 기록 주체는 시스템이지만 조회는 사람 액터다.

**사전조건**

1. 조회는 로그인 사용자. 기록은 UC04·UC07의 결과로 자동 발생.

**사후조건**

1. 이력에서 통제 전후 제공 값과 원본 값이 재현된다.
2. 원본 테이블에 대한 변경이 통제 경로에 없다.

**기본 흐름 (기록)**

1. 자동/수동 정보 통제, 계획 통제, 제공 차단, 현장 통제 요청이 발생한다.
2. 시스템이 시각, 액터, 유형, 교차로·방향, 원본 값, 제공 값(전/후), 이슈 ID를 저장한다.

**기본 흐름 (조회)**

1. 사용자가 교차로 상세 또는 통제 이력 화면을 연다.
2. 원본 잔여시간/점등상태와 제공(통제 후) 값을 나란히 본다.
3. 유형 필터로 AUTO_INFO / MANUAL_INFO / PLAN_UPDATE / PUBLISH_BLOCK / FIELD_REQUEST를 조회한다.

**수용 기준**

- 제공 값을 바꿔도 원본 행의 필드가 그대로이다.
- 통제 전후가 이력에서 재현된다.
- 운영자도 조회할 수 있으나 이력을 삭제·수정하지 못한다.

## 5. 대표 시나리오 (엔드투엔드)

테스트 E2E와 시연 스크립트의 뼈대다.

### 5.1 정상: 수집 → 검지 → 자동보정 → 관제

1. 시스템이 쿼터 안에서 표본을 수집한다 (UC01).
2. 잔여시간을 초로 정규화하고 원본/제공을 저장한다.
3. 계획과 조인한다. 매핑이 있으면 대조한다 (UC02, UC03).
4. 중복 수신(R08)을 제공 계층에서 제거하고 로그를 남긴다 (UC04).
5. 운영자가 대시보드에서 자동보정 건수와 정상 교차로를 확인한다 (UC06, UC11).

### 5.2 해결 불가: 계획 불일치 → 계획 통제

1. 점등상태가 계획과 지속적으로 어긋나 OPEN 이슈가 생긴다 (UC03, UC05).
2. 관리자가 ACK 후 계획을 수정하고 재검증한다 (UC07, UC02).
3. 정합하면 RESOLVED/CLOSED. `PLAN_UPDATE` 이력이 남고 원본은 유지된다 (UC11).

### 5.3 CRITICAL: 충돌 녹색 → 현장 통제 요청

1. R06 CRITICAL 이슈가 등록되고 제공이 차단된다 (UC05, FR-CTL-002).
2. 관리자가 현장 통제 요청을 남긴다. 신호기 API 호출은 없다 (UC07).
3. 운영자는 대시보드에서 “제공 중지”와 이슈를 본다. 값을 고칠 수는 없다 (UC06).

### 5.4 예외: 쿼터·API 장애·UTIC 미승인

| 시나리오 | 기대 |
|----------|------|
| 실시간 API 504 | 실패 기록·재시도, 웹 기동 유지, 부분 실패 우선 수집 |
| 쿼터 근접 | 호출 중단, 화면 경고 |
| UTIC 미승인 | 수동/추정/시드로 대조, 출처 표시, 결함 아님 |
| ID 미매핑 | 실시간 모니터링만, 계획 대조 생략 |
| 권한 없는 통제 | 거부 + 감사 로그 |

## 8. 백로그에 올리지 않는 것

아래는 스토리로 쪼개지 않는다. 구현 대상이 아니며 미구현을 결함으로 치지 않는다.

| 제외 | 이유 |
|------|------|
| 현장 신호제어기 점등·주기 실제어 | CON-003. UC07은 요청 기록만 |

| 고급 ML 이상탐지 | 규칙 엔진(R01~R12)으로 대체 |
| 경찰청 메타데이터관리시스템 | 문서 대체 |
| 센터 반입·보안 특약·1년 하자보수 | 문서·수업 대체 |

## 9. 검수 체크리스트

- UC01~UC11이 요구사항정의서 5.1과 ID가 같다
- 각 UC에 사전·사후·기본·예외와 수용 기준이 있다
- 필수 사용자 스토리에 Given에 해당하는 수용 기준이 있고 FR ID가 있다
- 운영자/관리자 권한 차이가 UC06·UC07·UC09에 드러난다
- 원본 불변이 UC01·UC04·UC07·UC11 수용 기준에 있다
- 현장 실제어가 유스케이스·스토리에 구현으로 적혀 있지 않다
- UTIC 미승인 대체(US-PLN-03)가 있다
- 쿼터 5,000(US-COL-05)이 있다
- 선택 스토리(푸시·지도) 미포함이 결함이 아니라고 적혀 있다
- E2E 시나리오 5.1~5.4가 시연 흐름과 맞다
