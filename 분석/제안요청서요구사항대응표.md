## 1. 개요

### 1.1 목적

본 문서는 제안요청서 **39개 요구**를 하나도 빠뜨리지 않고, Signal Guard가 **구현할지 / 표본 규모로 부분 구현할지 / 문서·수업으로 대체할지**를 고정한다.

요구사항 정의서는 “무엇을 만들지”를 ID로 분해한다. 본 문서는 “RFP 한 줄이 우리 산출물 어디에 붙는지”를 보여 준다.

```
제안요청서(RFP 39건)
        │
        ▼
본 대응표 (구현 / 부분 구현 / 문서·수업 대체)
        │
        ├──► 요구사항정의서 FR / NFR / DAR-N / CON
        └──► 설계서 · 테스트 계획 · 매뉴얼 · 일정
```

### 1.2 대응 구분

| 구분 | 의미 | 판정 |
|------|------|------|
| 구현 | RFP 의도를 수업 MVP에서 소프트웨어로 충족 | 12~13주 테스트로 통과/실패 |
| 부분 구현 | 의도는 같으나 규모·환경을 수업으로 축소 | 표본 교차로, 공개 API, 운영자/관리자 페르소나 |
| 문서·수업 대체 | 센터 반입·보안 특약·하자보수 등 발주 행정 | 구현 대상이 아님. 문서·발표·매뉴얼로만 남김 |

**수업에서 바꾸지 않는 것:** 원본 수신 불변, 검지→관제→통제 루프, 현장 신호기 실제어 제외.

**수업에서 바꾸는 것:** 전국 2,425개소·센터 내부망 → 인천 표본·공공 Open API. 경찰청 메타데이터관리시스템·보안 특약·1년 하자보수 → 문서 대체.

| 분류 | 건수 | 구현 | 부분 구현 | 문서·수업 대체 |

| SFR 기능 | 5 | 4 | 1 | 0 |
| PER 성능 | 4 | 1 | 3 | 0 |

## 3. 기능 요구사항 (SFR) — 5건, 핵심 구현 대상

### SFR-001 신호 모니터링시스템 구성 — 부분 구현

| 항목 | 내용 |
|------|------|
| RFP 요지 | 도시교통정보센터 기 구축 서버·네트워크를 활용한 최적 구성. 데이터 용량에 맞는 하드웨어, 확장 가능 구조, 서버 OS와 호환되는 사용자 SW. 산출: 시스템 구성도, 데이터 용량계산서 |
| 수업 해석 | 센터 인프라에 반입하지 않는다. 웹 앱 + API + DB + 수집 스케줄러 + 검지·관제·통제로 논리 구성을 제시한다. 교차로 수는 설정으로 늘린다. |
| 대응 방안 | 논리 구성도(프로젝트정의서 9.1). 용량 = 표본 교차로 수 × 수집 주기 × 보관 일. 스택은 4~5주차에 확정. |
| 관련 요구 | FR-SYS-001, FR-SYS-002, NFR-PER-003 |
| 수용 확인 | 로그인 후 대시보드·스케줄러·DB 저장이 동작. 구성도와 용량 산정이 산출물에 있다. |
| 비고 | 기 구축 센터 서버 재사용, 하드웨어 납품은 제외. |

### SFR-002 신호 데이터 수집 — 구현

| 항목 | 내용 |
|------|------|
| RFP 요지 | 현장에서 이미 수집·저장 중인 실시간 신호를 본 시스템으로 연동. 누락 방지 방안. 검증·모니터링에 적합한 포맷 변환. 산출: 데이터 설명서 |
| 수업 해석 | 센터 전용회선 대신 공공 실시간 API(`/crsrd_map_info`, `/tl_drct_info`)를 배치 수집한다. UTIC TOD는 승인 후, 그 전에는 대체 계획. |
| 대응 방안 | 인천 맵 수집, 8방향 상태 수집, 실패 재시도·부분 실패 우선 수집, 센티초→초 정규화, 일 5,000회 쿼터 가드. |
| 관련 요구 | FR-COL-001~005, FR-PLN-002~003, IF-EXT-001~002, CON-001 |
| 수용 확인 | 인천 교차로가 마스터에 쌓이고, 지정 주기로 상태가 저장되며, 당일 호출이 5,000을 넘지 않는다. |
| 비고 | 전국 2,425개소 동시 연계는 제외. 대조용 계획은 EXT-001로 보강. |

### SFR-003 신호 데이터 저장 및 관리 — 구현

| 항목 | 내용 |
|------|------|
| RFP 요지 | 센터 환경에 맞는 저장·관리. 일정 주기 저장. 일·주·월 단위 관리에 적합한 주기. |
| 수업 해석 | 원시 / 제공 계층 / 계획 / 검증 / 이슈 / 집계를 분리한다. 원본은 통제로 덮어쓰지 않는다. |
| 대응 방안 | 계층별 저장, 이력 보존, 시간·일·주·월 집계 배치. 통계 화면은 사전 집계를 읽는다. |
| 관련 요구 | FR-STO-001~003, FR-CTL-001, DAR-N-004 |
| 수용 확인 | 같은 수집 건의 원본과 제공 값을 각각 조회할 수 있다. 통계는 3초 이내. |
| 비고 | RFP의 “센터 인프라”는 수업 DB로 대체. |

### SFR-004 신호 데이터 검증 — 구현

| 항목 | 내용 |
|------|------|
| RFP 요지 | 실시간 신호의 오류 판정. 정보 입력 상태, 오류 여부, 정합성·일관성. 교차로 운영상태, 통계/분석. 추가 검증 항목 도출. 산출: 데이터 검증 설계서 |
| 수업 해석 | RFP가 비워 둔 “무엇과 비교할지”를 **신호 계획 vs 실시간 상태**로 채운다. 규칙은 R01~R12. |
| 대응 방안 | 설정 테이블 임계값, 등급 INFO/WARN/ERROR/CRITICAL, 해결 가능은 자동 정보 통제, 해결 불가는 이슈. |
| 관련 요구 | FR-VAL-001~006, R01~R12, EXT-001~002 |
| 수용 확인 | 규칙별 정상/경계/오류 테스트가 기대 판정과 일치한다. 충돌 녹색은 CRITICAL. |
| 비고 | 고급 ML 이상탐지는 제외. |

### SFR-005 신호 모니터링 프로그램 — 구현

| 항목 | 내용 |
|------|------|
| RFP 요지 | 종합 대시보드(차트). 실시간 오류 내역. 이슈 등록·관리. 이력/통계 조회·출력. 계정·권한·메뉴. 권한은 발주처 승인 후. 산출: 화면(UI)설계서 |
| 수업 해석 | 관제(대시보드·이슈)와 통제(정보·계획·현장 요청) 화면을 포함한다. 역할은 운영자/관리자. |
| 대응 방안 | 대시보드, 교차로 상세(원본/제공 병기), 이슈 생명주기, 통계 CSV, 로그인·RBAC, 설정. 푸시·지도는 선택. |
| 관련 요구 | FR-MON-001~006, FR-ISS-001~004, FR-ADM-001~002, FR-CTL-002~005 |
| 수용 확인 | 로그인 직후 지표가 보이고, 운영자는 값/계획을 수정할 수 없으며, 필터·CSV가 동작한다. |
| 비고 | 발주처 권한 승인은 팀 역할표로 대체. 웹소켓은 폴링 가능. |

## 4. 성능 요구사항 (PER) — 4건

### PER-001 센터 소프트웨어 — 부분 구현

### DAR-001 데이터 표준 수립 및 상위표준 준수 — 부분 구현

### DAR-002 데이터 표준관리 — 문서·수업 대체

### DAR-003 데이터 구조 설계 — 부분 구현

### DAR-004 데이터 구조 검증 — 문서·수업 대체

### DAR-005 데이터 구조관리 — 문서·수업 대체

## 8. 보안 요구사항 (SCR) — 7건

센터 내부망, 누출금지정보, 전문 보안점검 도구, 관리자 페이지 IP 제한은 **구현하지 않는다.** 수업에서 지키는 최소 집합은 RBAC, 비밀번호 해시, 입력 검증, 시크릿 미커밋, 감사 로그이다.

### SCR-001 국가 표준 지침 준수 — 부분 구현

RFP가 열거한 행안부·국정원·W3C·접근성 지침 중, 웹 표준(SIR-001)과 개발보안 기본(입력 검증, 인증)만 적용한다. 전체 지침 체크리스트는 문서에 인용하고 적용 범위를 “수업”으로 표시한다.

관련: NFR-SEC-001~002, NFR-USA-001.

### SCR-002 보안 특약사항 — 문서·수업 대체

누출금지정보(센터 IP, 구성도, 소스 무단 반출 등)와 부정당업체 조항은 발주 계약 항목이다. 수업 과제는 공개 API와 팀 저장소만 다룬다. **구현 제외, 결함 아님.**

### SCR-003 보안 지침 준수 — 부분 구현

RBAC, 세션/토큰 만료, 권한 없는 API 403, 산출물에서 인증키 평문 금지. 관련: NFR-SEC-001~003, FR-ADM-001.

### SCR-004 보안코딩 및 보안취약점 제거 — 부분 구현

인증 우회, 주요 입력 검증, SQL/XSS 기본 점검을 테스트 주에 한다. OWASP Top 10 자동화 도구·웹취약점 점검결과서 형식은 수업용 점검표로 축소한다. 시크릿 하드코딩 금지.

관련: NFR-SEC-002.

### SCR-005 개인정보보호 및 데이터 암호화 — 부분 구현

본 시스템은 교차로 신호 데이터를 다루며 **주민번호·연락처 등 개인정보를 수집하지 않는다.** 계정 비밀번호만 복호화 불가 해시로 저장한다. DB 전수 암호화·개인정보 전송 암호화는 개인정보 항목이 생길 때만 해당한다.

관련: NFR-SEC-002, COR-003.

### SCR-006 기술적 보안관리 — 부분 구현

관리자/운영자 기능을 권한으로 분리한다. 내부망 전용 관리자 페이지, 특정 IP만 허용, FTP/Telnet 제거, 전문 취약점 점검은 센터 환경 항목으로 제외한다.

관련: FR-ADM-001, NFR-SEC-001.

### SCR-007 시큐어 코딩 가이드 준수 — 부분 구현

언어는 4~5주차 확정. Java면 시큐어코딩 가이드 기본 항목, 그 외 언어면 동등한 입력 검증·출력 인코딩·시크릿 관리. 전체 영향 영역 상용 진단 도구는 제외.

관련: NFR-SEC-002, CON-005.
